1. The Role of the Operating System:

In the `ultimate_cluster_os.py` script, the AI Cluster OS simulated several major Operating System responsibilities:

- File System & Permissions (Lab 9): The os.path.isfile(dataset_path) check verified that the required dataset file existed before executing a job. Workload D failed because secret_keys.txt did not exist, so the system rejected the job before allocating resources.

- Memory Management (Labs 5/6): The system used a while loop and ram_lock to check whether sufficient RAM was available. If the requested RAM exceeded the available memory, the job waited instead of starting immediately. This prevented memory over-allocation and reduced the risk of Thrashing.

- Concurrency & Deadlocks (Labs 3/4): The system sorted requested GPU IDs using sorted(req_gpus) before acquiring GPU locks. All jobs acquired GPU resources in a consistent order, preventing Circular Wait deadlocks.

- CPU Scheduling (Lab 7): The job_queue and scheduler thread managed incoming AI workloads. Each accepted job was assigned to a worker thread, allowing multiple jobs to execute concurrently.

2. Hardware Utilization:

Based on the Live Dashboard results:
- Workload A (LLaMA Training) allocated 40 GB of RAM and acquired GPUs 0, 1, and 2.
- Workload B (Preprocessing) allocated 16 GB of RAM and ran on the CPU without requiring any GPU.

- Concurrent Execution: All three workloads ran simultaneously because the system had sufficient RAM and their GPU requirements did not conflict.
- Resource Utilization: The three workloads used a total of 58 GB RAM, leaving 6 GB available while all four GPUs were occupied.

- Resource Recovery: After all jobs finished, the available RAM returned to 64/64 GB, all GPUs became IDLE, and the active job count returned to zero.
