1. FIFO vs LRU (Phase 2):

In the `page_replacement.py` script, the LRU algorithm performed better than FIFO because:
- FIFO (First-In, First-Out) removed the page that had been in RAM the longest, regardless of how recently it was accessed.
- LRU (Least Recently Used) removed the page that had not been accessed for the longest time.
- Whenever a page was accessed, LRU updated its position in the list to mark it as the most recently used.
- With 3 physical memory frames, LRU produced 7 page faults, while the expected FIFO result was 9 page faults.
- As a result, LRU reduced unnecessary page replacements by considering the recent memory access pattern.

2. Understanding Thrashing (Phase 3):

Based on the results from `ai_thrashing.py`:
- Definition: Thrashing occurs when the operating system spends excessive time swapping pages between RAM and disk instead of executing processes.
- Scenario 1 (RAM Access): The processing time was 0.8898 seconds.
- Scenario 2 (Disk Access): The processing time was 1.9318 seconds.
- Performance Impact: Scenario 2 was approximately 2.17 times slower than Scenario 1.
- Reason: Scenario 2 repeatedly opened a file and performed disk read and write operations. These additional operations increased processing time compared with accessing data directly in RAM.

3. AI Engineering Decision:

Lowering the `batch_size` in an AI training program helps reduce Thrashing as follows:
- Memory Reduction: A smaller batch_size processes fewer training samples simultaneously, reducing the amount of RAM required during each training step.
- Reduced Swapping: When memory usage decreases, the operating system has less need to move pages between RAM and disk.
- Improved Performance: Reducing excessive disk I/O allows the CPU to spend more time processing the AI model instead of waiting for memory operations.
- Trade-off: A smaller batch_size may require more training iterations to process the entire dataset, but it can prevent severe performance degradation caused by Thrashing.
